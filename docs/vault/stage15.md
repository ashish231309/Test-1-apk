# Stage 15 — Photos, Videos, Audio & Document Vault

## Scope and retained architecture

Stage 15 adds MIME-based presentation to the existing Stage 13–14 vault. It preserves the selected SAF root, metadata envelope, device-wrapped vault content key, authenticated index and object format, Stage 2 cryptography, existing `SessionManager`, and current navigation. It adds no storage root, key hierarchy, crypto service, index, item repository, authentication path, or session. `VaultContentClassifier` is Android-free and derives its result only from each authenticated `VaultItem.originalMimeType`; it changes no persisted item. A missing or invalid MIME is `Other`/unknown. Filename and extension inference is deliberately absent.

The main implementation boundaries are `VaultContentPresentationGateway`, the platform `AndroidVaultContentPresentationRepository`, `AndroidVaultImageDecoder`, `VaultItemViewerViewModel`, and the existing vault screen. The ViewModel keeps only typed state and an opaque random handle; it does not carry a stream, cipher, key, URI, path, bitmap, plaintext buffer, or viewer content. The gateway rechecks the existing authorized session and an operation checkpoint before and after sensitive work. It does not establish, extend, refresh, or lock sessions.

## Implemented preview behavior and format distinctions

- **Images:** bounded, in-memory preview is implemented for authenticated images with supported image MIME values (JPEG, PNG, WebP, GIF, BMP, HEIC/HEIF, and AVIF where the adapter's API gate permits). The actual platform decoder and device codec determine whether a particular image can be decoded; only PNG has a generated-image Android instrumented fixture in this change. Decoder inability, unsupported platform codecs, and malformed image data cannot always be distinguished through `BitmapFactory` and remain unverified on device. Image types are classified separately from any promise that a device can render them.
- **Plain text:** `text/plain` is decoded as strict UTF-8 and previewed only up to 256 KiB. Invalid UTF-8 is a corrupt-format result. Text MIME types other than `text/plain` remain recognized as documents but unsupported for rendering.
- **PDF:** `application/pdf` is recognized as a document but **not rendered**. It receives the explicit unsupported-preview state.
- **Audio and video:** common MIME values are classified as audio/video but playback is **not implemented**. Android `MediaPlayer` requires seekable/random-access input for practical playback, while the existing object format and authenticated GCM decryption path are sequential. This stage intentionally does not stage the full plaintext file in app-private storage or materialize it as a whole-file byte array. The UI therefore reports these items as unsupported rather than exposing unauthenticated plaintext or claiming platform playback.
- **Other documents and generic files:** office, OpenDocument, and other document MIME values can be represented in the authenticated item list but are not opened in a platform document viewer. Unknown/generic items likewise retain metadata and receive an unsupported fallback. No external open-with, provider hand-off, or export path is present.

The list's MIME category is descriptive, not a supported-format promise. A format being recognized as Image/Video/Audio/Document does not mean that a viewer exists. In particular, only the bounded image path and bounded plain-text path are implemented; PDF, audio, video, and other documents are not supported for preview in this stage and receive explicit unsupported states.

## Authenticated read and bounded memory

The presenter first finds the item by ID in a successfully authenticated current index read; it does not trust a caller-supplied record as the source of metadata. It opens the matching generated encrypted object through the existing read-only `VaultContentStorage` boundary and delegates all decryption to Stage 14 `VaultContentCrypto.decryptObjectToQuarantine`. That API's quarantine contract withholds usable content until the existing streaming GCM operation returns successfully after final tag verification. Authentication failure is a distinct typed result and no viewer handle or preview is returned.

Image ciphertext is decrypted into a bounded wiping in-memory quarantine (maximum compressed input 16 MiB), then sampled to a maximum 1,536-pixel render dimension. The preview buffer is wiped after decode; the bitmap is retained only under the opaque handle and recycled on close. Strict UTF-8 text is decrypted into a bounded wiping in-memory quarantine (maximum 256 KiB); its mutable character storage is zero-filled on resource close. No decrypted content is written to a temporary file, cache directory, database, SAF document, thumbnail store, or index. No whole audio/video/document byte array is allocated.

Android image decoding may allocate transient decoder buffers and platform bitmap memory. The compressed-input, source-dimension, and sampled-output caps bound expected use but cannot guarantee that all devices avoid allocation failure. Unsupported/corrupt decoder outcomes are per-item and do not change the index or remove list entries.

## List, diagnostics, and non-mutation

The list shows authenticated metadata rows, display MIME/category, size, and imported date in existing index order, loading them in bounded 100-item batches so every row remains reachable; it has no album, advanced search, sorting, tagging, or organization controls. Per-item failures distinguish unsupported preview, missing object, unreadable object, GCM authentication failure, unsupported encrypted-object version, corrupt format, authorization expiry, and generic viewer failure. A failing row does not erase other rows.

Index diagnostics retain visible missing-content and objects-without-index states. `ContentWithoutIndex` also reports unindexed and unfinished-object counts when an inventory is available. The presentation feature never scans to reconstruct the index, imports an orphan, repairs a snapshot, deletes an object, or mutates the authenticated index. Read-only inventory can be provider-dependent; an unavailable inventory remains an explicit diagnostic limitation rather than an empty-vault claim.

## Session, lifecycle, and privacy

Opening requires both the existing `SessionManager` authorization and the operation checkpoint. Viewer code does not invoke primary or biometric authentication, create/refresh a session, extend the session timeout, or call Quick Lock. The platform gateway observes the existing session state and closes its resources on unauthenticated state or when a different authenticated session replaces the prior one (so a rapid Quick Lock/re-auth is not trusted to be observed as two distinct `StateFlow` emissions); the ViewModel also closes its opaque handle on session invalidation, explicit close, screen disposal, Activity pause, and ViewModel clearing. Closing is idempotent. Compose clears copied image pixels and recycles its temporary display bitmap when the image composition is disposed.

The vault destination uses the existing `SecureScreenEffect` to block screenshots/recents capture while sensitive names and previews are visible. The viewer ViewModel's state is not saved through `SavedStateHandle` and contains only status, page/playback metadata, and an opaque handle. No raw URI, path, stream, cipher, key, or plaintext image/text is put in viewer state. The UI displays authenticated text as runtime composable content; it is not intentionally persisted or logged. Source filenames and content are not written to logs. No plaintext cache is used and no permissions are added for this stage: there is no network, sharing/export, broad storage/media permission, thumbnail infrastructure, analytics, or telemetry.

## Tests and unverified behavior

Android-free JVM tests cover MIME classification/conservative fallback, viewer authorization and Quick Lock cleanup through fake sessions, typed unsupported object-version handling, and inventory diagnostics. The Stage 14 crypto integration test is extended to exercise authenticated quarantine success and GCM tamper rejection. Android instrumented image-decoder tests use generated PNG, malformed-byte, and oversized-dimension fixtures. A presenter lifecycle instrumented test injects a fake successful quarantine result to check Quick Lock resource closure; it does not test GCM (that is covered by the Stage 14 crypto integration tests).

Local static validation: `python3 tools/verify_nivara.py` passes, and `python3 -m unittest tools/test_verify_hidden_architecture.py tools/test_verify_launcher_architecture.py tools/test_verify_camouflage_architecture.py tools/test_verify_vault_architecture.py` passes all 81 tests. The Stage 15 verifier rules are individually negative-tested with source fixtures that are restored byte-for-byte. No Gradle compilation, Kotlin/JVM test execution, Android instrumented test execution, CI, or device run has completed: this workspace has no `java`/`javac` executable or configured `JAVA_HOME`. Android framework/API compatibility, platform codec support, real SAF-provider behavior, lifecycle timing, Quick Lock races, memory behavior on low-RAM devices, and TalkBack presentation remain unverified. No playback support is claimed.

## Deferred scope and next stage

Stage 15 itself did not include albums, search, sorting, trash, restore, recovery/reinstallation, cloud backup, sharing/export, persistent thumbnails, source modification, automatic repair, analytics, or telemetry. Stage 16 subsequently added album organization, metadata-only search, sorting, and stale-reference visibility; Stage 17 now adds reversible Trash/Restore metadata transitions without changing the Stage 15 viewer or encrypted object format. See [stage16.md](stage16.md) and [stage17.md](stage17.md) for their current scope and verification status. Recovery/reinstallation remains deferred to Stage 18.
